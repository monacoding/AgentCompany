# Project 협업 플레이북 요약

## 표준 절차 (5단계)

1. **목표 설정**
   - 사장님의 지시로부터 명확한 한 문장 목표를 설정하고, 산출물, 범위 및 제외 항목을 알아봅니다.

2. **계획 수립**
   - 프로젝트를 리서치, 구현/실행, 검증, PM 보고의 단계로 나눕니다.
   - 각 태스크는 최대 5회의 `작업 → 검토 루프`를 통해 완성되며, FINISHED를 키워드로 활용합니다.

3. **작업 분배**
   - `번호 + @에이전트명: 할 일` 형식으로 작업을 분배합니다.
   - 예: `1. @한서준: 공식 PDF 출처 URL 조사`

4. **에이전트 선별**
   - 실제 회사 에이전트 로스터만을 사용하며 가상 직함, 외부 인력은 금지됩니다.
   - 역할 및 능력치에 따라 적절한 에이전트를 매칭합니다.

5. **승인 후 프로젝트 실행**
   - PM이 사장님에게 계획을 제시하고 "진행하세요" 승인을 요청합니다.
   - 승인되면 프로젝트 채팅방이 생성되고 에이전트가 순차적으로 협업을 시작합니다.
   - 산출물은 `company/projects/{sessionId}/`에 저장되고 이전 태스크의 산출물은 carry_data를 통해 전달됩니다.

## PM 1:1 대화 형식 (권장)

```markdown
## 목표
(한 문장)

## 계획
P1 … / P2 … / P3 …

## 작업 분배
1. @에이전트명: 할 일
2. @에이전트명: 할 일

## 참여 에이전트
@박준호 · @한서준 · …

확정되시면 "진행하세요"라고 말씀해 주시면 Project를 시작합니다.
```

## 하정우 — Project 자동화 역할
- 이전 태스크의 `carry_data`의 URL 및 fileSeq를 기반으로 스크립트를 구현.
- 산출물을 `company/projects/{sessionId}/files/`에 저장.
- Python urllib/curl 등을 활용해 실제 다운로드 후 %PDF 헤더를 검증.
