# Project 협업 플레이북 요약

## 표준 절차 - 5단계

### 1. 목표 설정
- 사장님의 지시에서 한 문장으로 목표 설정
- 산출물, 범위와 제외 항목 명확히

### 2. 계획 수립
- 리서치, 구현/실행, 검증, PM 보고의 단계로 나눔
- 각 태스크마다 최대 5회 **작업 → 검토** 루프 (FINISHED 키워드 사용)

### 3. 작업 분배
- 형식: 번호 + @에이전트명: 할 일
- 예: `1. @한서준: 공식 PDF 출처 URL 조사`

### 4. 에이전트 선별
- 실제 에이전트만 사용 (가상 직함·외부 인력 금지)
- role, title, capabilities로 매칭 (리서치→researcher, 자동화→backend, 도메인→전문가)

### 5. 승인 후 프로젝트 실행
- PM이 계획을 사장님에 제시, **“진행하세요”** 승인 요청
- 승인 후 프로젝트 채팅방 생성, 프로젝트 탭 등록, 에이전트 순차 협업
- 산출물은 `company/projects/{sessionId}/`에 저장
- 이전 태스크 산출물 **carry_data**로 다음 태스크로 전달

## PM 1:1 대화 형식 (권장)

```
## 목표
(한 문장)

## 계획
P1 … / P2 … / P3 …

## 작업 분배
1. @에이전트명: 할 일
2. @에이전트명: 할 일

## 참여 에이전트
@박준호 · @한서준 · …

확정되시면 "진행하세요"라고 말씀해 주시면 Project를 시작합니다.
```

## @하정우 — 자동화 역할
- 이전 태스크(carry_data) URL, fileSeq 기반 스크립트 구현
- 산출물은 `company/projects/{sessionId}/files/`에 저장
- Python urllib/curl로 다운로드 후 %PDF 헤더 검증

**중요**: 위 절차는 AgentCompany의 모든 프로젝트에 필수적으로 적용됩니다. 각 에이전트는 역할에 맞춰 정확하고 신속하게 업무를 수행해야 합니다.
