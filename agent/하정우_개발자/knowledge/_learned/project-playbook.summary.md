# Project 협업 플레이북 요약

## AgentCompany Project 표준 절차

- PM이 사장님으로부터 지시받은 업무 수행 시 **5단계**를 따릅니다.

### 1. 목표 설정
- 사장님 지시에서 명확한 **한 문장 목표** 및 산출물, 작업 범위 등을 정의합니다.

### 2. 계획 수립
- Phase 단위로 작업을 나눔 (리서치 → 구현/실행 → 검증 → PM 보고).
- 각 태스크마다 **작업 → 검토 루프** 운영(최대 5회, "FINISHED" 키워드 사용).

### 3. 작업 분배
- 계획서에 **번호 + @에이전트명: 할 일** 형식으로 작성.
- 예: `1. @한서준: 공식 PDF 출처 URL 조사`.

### 4. 에이전트 선별
- **실제 회사 에이전트 명단만** 사용 (가상 직함·외부 인력 금지).
- 역할, 타이틀, 역량에 맞춰 매칭 (예: 리서치→Researcher, 자동화→Backend).

### 5. 승인 및 실행
- PM이 계획을 사장님께 보고하여 **"진행하세요"** 승인을 요청.
- 승인 후 Project 채팅방 생성, Projects 탭 등록 및 순차적 작업.
- 산출물 저장: `company/projects/{sessionId}/` 경로에 저장.
- 이전 태스크 산출물은 **carry_data**로 다음 태스크에 전달.

## PM 1:1 대화 형식 (권장)

```
## 목표
(한 문장)

## 계획
P1 … / P2 … / P3 …

## 작업 분배
1. @에이전트명: 할 일
2. @에이전트명: 할 일

## 참여 에이전트
@박준호 · @한서준 · …

확정되시면 "진행하세요"라고 말씀해 주시면 Project를 시작합니다.
```

## @하정우 — 자동화 역할
- 이전 태스크의 URL, fileSeq를 기반으로 스크립트 구현.
- 산출물은 `company/projects/{sessionId}/files/`에 저장.
- Python urllib/curl 등으로 실제 파일 다운로드 및 %PDF 헤더 검증 실시.
