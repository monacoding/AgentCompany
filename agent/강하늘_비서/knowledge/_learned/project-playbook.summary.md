# `project-playbook.md` 요약 — 강하늘(PM)

- **PM 필수 절차**
  - 사장님이 업무를 지시하면 즉시 실행하지 말고 먼저 아래 4블록을 제시:
    - **목표**
    - **계획**
    - **작업 분배**
    - **참여 에이전트**
  - 이후 사장님의 승인 키워드가 있어야 Project를 시작한다.

- **1단계: 목표 정의**
  - 사장님 지시를 바탕으로 **한 문장 목표**를 작성한다.
  - 반드시 포함할 것:
    - 산출물
    - 작업 범위
    - 제외 항목

- **2단계: 계획 수립**
  - Phase 단위로 구성:
    - 리서치
    - 구현/실행
    - 검증
    - PM 보고
  - 각 태스크는 **작업 → 검토 루프**를 수행한다.
  - 검토 루프는 최대 **5회**까지 가능하며, 완료 시 **FINISHED** 키워드를 사용한다.

- **3단계: 작업 분배**
  - 작업은 반드시 아래 형식으로 작성:
    - `1. @에이전트명: 할 일`
  - 예:
    - `1. @한서준: 공식 PDF 출처 URL 조사`

- **4단계: 에이전트 선별**
  - 반드시 **실제 회사 roster에 있는 에이전트만** 사용한다.
  - 가상의 직함, 외부 인력, 임의 에이전트 생성 금지.
  - role, title, capabilities를 기준으로 매칭한다.
    - 리서치 → researcher
    - 자동화/스크립트 → backend
    - 도메인 검증 → 전문가

- **5단계: 승인 후 실행**
  - PM은 계획을 제시한 뒤 다음 문구로 승인을 요청:
    - `확정되시면 "진행하세요"라고 말씀해 주시면 Project를 시작합니다.`
  - 승인 키워드:
    - `진행하세요`
    - `시작하세요`
    - `프로젝트 진행`
  - 승인 전에는 **Project 채팅방을 열지 않는다.**

- **Project 실행 방식**
  - 승인 후:
    - Project 채팅방 생성
    - Projects 탭 등록
    - 에이전트 순차 협업
  - 산출물 저장 위치:
    - `company/projects/{sessionId}/`
    - `tasks/`
    - `files/`
    - `PM_REPORT.md`
  - 이전 태스크 산출물은 **carry_data**로 다음 태스크에 전달한다.

- **특수 업무 규칙**
  - 인터넷·웹 PDF 다운로드 요청 시:
    - `knowledge/` 또는 로컬 폴더 검색 금지
    - 외부 수집 Project로 계획
  - PDF/수집 업무 권장 순서:
    - `@한서준` 출처 조사
    - `@하정우` 스크립트/Kilo 실행
    - 도메인 전문가 검증
  - 영상/콘텐츠 업무:
    - `@서윤아델린 + @하정우` 조합 검토.
