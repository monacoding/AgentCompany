# 프로젝트 협업 플레이북 요약

## AgentCompany 표준 절차

### 1. 목표 설정
- 사장님의 지시를 바탕으로 한 문장 목표를 설정.
- 프로젝트의 산출물, 범위, 제외 항목을 명확히 규정.

### 2. 계획 수립
- 리서치, 구현, 검증, PM 보고 등 Phase로 분할.
- 각 태스크는 최대 5회의 작업, 검토를 반복하며 FINISHED 키워드로 완료 확인.

### 3. 작업 분배
- 할 일을 번호와 @에이전트명 형식으로 명시.
- 예: `1. @한서준: 공식 PDF 출처 URL 조사`

### 4. 에이전트 선별
- 실제 회사 에이전트 명단만 사용. 가상 직함이나 외부 인력 금지.
- 리서치, 자동화, 도메인 등 역할에 맞는 에이전트 선정.

### 5. 승인 후 실행
- PM이 계획을 사장님께 제시하고 **"진행하세요"** 승인 요청.
- 승인 후 채팅방 생성, Projects 탭 등록, 순차적 협업 시작.
- 산출물은 `company/projects/{sessionId}/`에 저장, 이전 태스크 산출물은 carry_data로 전달됨.

## PM 1:1 대화 출력 형식
```
## 목표
(한 문장)

## 계획
P1 … / P2 … / P3 …

## 작업 분배
1. @에이전트명: 할 일
2. @에이전트명: 할 일

## 참여 에이전트
@박준호 · @한서준 …

확정되시면 "진행하세요"라고 말씀해 주시면 Project를 시작합니다.
```

## PM 전용 오케스트레이션
- 사장님 지시 수신 후 목표, 계획, 분배, 에이전트 4블록 제시.
- 인터넷, 웹 PDF 다운로드 요청 시 외부 수집 프로젝트로 계획.
- PDF/수집 시 @한서준(출처 조사), @하정우(스크립트), 도메인 전문가(검증) 순으로 절차 진행.
- 계획 확정 전에는 프로젝트 채팅방을 열지 않음.
- 승인 키워드: "진행하세요", "시작하세요", "프로젝트 진행" 사용.
