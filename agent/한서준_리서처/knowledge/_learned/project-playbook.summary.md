# Project 협업 플레이북 요약

## AgentCompany Project 표준 절차 (필수)

### 1. 목표
- 사장님의 지시에서 **한 문장 목표** 도출.
- 산출물, 범위, 제외 항목 구체화.

### 2. 계획
- 프로젝트를 Phase 단위로 구분 (리서치 → 구현/실행 → 검증 → PM 보고).
- 각 태스크는 **작업 → 검토 루프** 진행 (최대 5회, FINISHED 키워드 사용).

### 3. 작업 분배
- 계획을 **번호 + @에이전트명: 할 일** 형식으로 명시.
- 예: `1. @한서준: 공식 PDF 출처 URL 조사`

### 4. 에이전트 선별
- **실제 회사 에이전트 roster**만 사용 (가상 직함 및 외부 인력 사용 금지).
- 역할, 직함, 역량에 맞춰 에이전트 매칭.

### 5. 승인 후 Project 실행
- PM이 사장님께 계획을 제시하고 **"진행하세요"** 승인을 요청.
- 승인 시: Project 채팅방 생성 → Projects 탭에 등록 → 에이전트 순차 협업.
- 산출물: `company/projects/{sessionId}/` 경로에 저장.
- 이전 태스크 산출물은 **carry_data**로 다음 태스크에 전달.

## PM 1:1 대화 출력 형식 (권장)
```
## 목표
(한 문장)

## 계획
P1 … / P2 … / P3 …

## 작업 분배
1. @에이전트명: 할 일
2. @에이전트명: 할 일

## 참여 에이전트
@agent1 · @agent2 · …

확정되시면 "진행하세요"라고 말씀해 주시면 Project를 시작합니다.
```

## PM 전용 — Project 오케스트레이션
- **목표·계획·분배·에이전트** 4블록을 사전 제시.
- roster에 없는 인물·역할을 만들지 말 것.
- PDF/수집 업무: @한서준(출처) → @하정우(스크립트) → 도메인 전문가(검증) 순.
- 인터넷 PDF 다운로드 시 로컬 파일 검색 금지. 외부 수집 Project로 계획.
- 프로젝트 승인 키워드: "진행하세요", "시작하세요", "프로젝트 진행".
- 계획 확정 전 채팅방 개설 금지. 

### 추가사항
- 사장님 지시 수신 후 빠르게 목표 및 계획 설정.
- 작업과 검토 루프는 반드시 5회 이내로 제한.
- 모든 생성된 산출물은 지정된 경로에 저장하여 체계적인 관리.
