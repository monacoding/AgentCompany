# 프로젝트 협업 플레이북 요약

## AgentCompany 프로젝트 표준 절차

### 1. 목표 설정
- 사장님의 지시에서 한 문장으로 목표를 설정.
- 산출물, 범위, 제외 항목을 명확히 정의.

### 2. 계획 수립
- 프로젝트를 Phase로 나눈다: 리서치 → 구현/실행 → 검증 → PM 보고.
- 작업 검토 루프는 최대 5회 반복, FINISHED 키워드로 마무리.

### 3. 작업 분배
- 각 업무를 번호 + @에이전트명: 할 일 형식으로 기록.
- 예: `1. @한서준: 공식 PDF 출처 URL 조사`

### 4. 에이전트 선별
- 실제 회사 에이전트 roster만 사용.
- 역량에 맞게 role, title, capabilities로 매칭.

### 5. 승인 후 프로젝트 실행
- PM은 계획을 사장님께 제시 후 승인 요청.
- 승인되면 프로젝트 채팅방 생성, 순차적 협업 진행.
- 산출물 및 데이터는 carry_data로 다음 작업에 전달.

## PM 1:1 대화 출력 형식

- 목표, 계획, 작업 분배, 참여 에이전트 4블록으로 구성.
- 확정되면 '진행하세요' 요청으로 프로젝트 시작.

## PM 전용 — 프로젝트 오케스트레이션

- 4블록 준비: 목표, 계획, 분배, 에이전트.
- 가상 직함 및 외부 인력 사용 금지.
- PDF, 수집 업무: @한서준(출처) → @하정우(스크립트) → 도메인 전문가.
- 컨텐츠 작업: @서윤아델린 + @하정우 조합.
- 채팅방은 계획 확정 후 개설.
- 승인 키워드: '진행하세요', '시작하세요', '프로젝트 진행'.

## 참고 규칙

- 인터넷/웹에서 PDF 다운로드 요청 시 내부 파일 검색 금지, 외부 프로젝트로 계획.
- @한서준: 리서치 실행, @하정우: 스크립트 실행.
- 승인 후 공식 절차대로 프로젝트 실행.
